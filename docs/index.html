Contact 2 Post

version

WordPress

ver-1.4.0

When a Contact Form 7 form is submitted, this plugin saves the uploaded image files to the Media Library. Then, after Flamingo saves the message, this plugin can create a "pending post" from a template post page. The first uploaded image is attached as the post's featured image

Installation

  1. Install contact-form-7 plugin.
    • Rollback to version 6.1.7, if date fields don't work. For why see issue: https://github.com/TurtleEngr/WP-contact-2-post/issues/1 Install "WP Rollback" plugin to rollback.
  2. Install flamingo plugin.
  3. Optional: Install ninja-auto-post-expire plugin
  4. If save-cf7-file-uploads is installed, delete it. It is not compatible with this plugin.
  5. Install and activate this plugin contact-2-post

Development Installs

These are not stable versions. ver-1.4.0-rel is the current stable version.

  1. Follow Installation steps 1 to 3 above.
  2. Go to: https://moria.whyayh.com/rel/released/software/own/WP-contact-2-post
  3. Then download the contact-2-VER.zip file you want.
  4. In WordPress, install with Upload Plugin, then activate.

Usage

To use this plugin, you need to add some things to your contact forms. See "Contact Form Settings" section.

Also, you need to define a template for your posts. See "Template Page" section.

Uploaded images are saved for every form, even without create_post. See "Uploaded Files" section.

If you installed ninja-auto-post-expire, you will the "Post" option needs to be set to "Yes" in its Post Expire Settings.

Contact Form Settings

In a form's "Additional Settings" tab, add these settings:

create_post: true
post_template: PageSlug
skip_mail: on
do_not_store: false

  • create_post - this contact-2-post plugin option. If 'true' that activates this plugin

  • post_template - this contact-2-post plugin option. This is the "slug-name" for a "page" that will be used as a template to generate a "Pending" post from a form. See "Template Page" for details.

  • skip_mail - contact-form-7 plugin option. This has no effect on the contact-2-post plugin, but you can decide if you want to send an email of the form, in addition to making a post.

  • do_not_store - flamingo plugin option. The default is 'false'. If it is set to 'true', the form data will not be stored and this contact-2-post plugin will not work.

While this plugin does not "publish" the posts, you should turn on reCAPTCHA in contact-form-7 settings so your admin doesn't get spammed with bot submitted "Pending" posts.

Template Page

All the blocks of the 'PageSlug' page are copied to the new post. {field} is replaced with the value of the form 'field' with that name. Values are HTML escaped, and "[" "]" in values are encoded so they cannot run a shortcode. Checkbox values are joined with ", ". If there is no field with that name, {field} is left as is.

Textarea fields are the exception: they can have some HTML. When HTML text is pasted into a form's textarea, it is cleaned, and the textarea shows the HTML tags that are kept. Only these tags are kept: h1, h2, h3, h4, a, p, b, strong, i, em, ul, ol, li, br. All attributes are removed, except href on "a" tags, and only for http, https, or mailto URLs. Other tags are removed (their text is kept), and script and style elements are removed with their content. The same cleaning is done again when the post is created. If a textarea value has none of the allowed tags, it is escaped like other fields.

So the post can be edited in the block editor, a {field} with p, h1-h4, ul, or ol tags is changed to blocks: Paragraph, Heading, and List blocks. This only works when the {field} is in a Paragraph block in the template. Any text before or after the {field} in that paragraph is put in its own paragraph. In other blocks (for example a Heading), only the inline tags are kept, and the block tags are changed to line breaks.

A post has attributes that are not blocks. This is how they are defined in the page template. After the page's title, put the post's attribute lines between ATTR-BEGIN and ATTR-END lines (one per line, or separated with Shift-Enter). They can be in one top-level block or in several. Every top-level block from the one with ATTR-BEGIN to the one with ATTR-END are not copied. They are used to set the post's attributes. FYI, all these are optional.

ATTR-BEGIN
title: {your-subject}
categories: {field}
tags: {field}
publish-date: {field}
expire-date: {field}
expire-time: {field}
ATTR-END
  • title - post title. See Flamingo documentation for how to change {your-subject} Default: UNDEFINED
  • categories, tags - comma separated names or slugs. Only existing categories and tags are used; others are ignored. Default: empty
  • publish-date - YYYY-MM-DD, time is set to 12:00. This date is kept when the post is published (a future date makes it "Scheduled"). Default: the time the post is published.
  • expire-date - YYYY-MM-DD. Saved in the ninja-auto-post-expire meta (_njtape_expiration_date). Default: not set.
  • expire-time - HH:MM. Default: 00:00

ninja-auto-post-expire only acts on posts if its "Post" option is set to "Yes" in it's settings, Post Expire Settings.

Invalid dates or times are ignored. An invalid expire-date is also reported. See "Error Reports".

Uploaded Files

Files uploaded with the Contact Form 7 [file NAME] field are saved to the Media Library before the email is sent.

  1. Only image files are saved. The type is checked from the file content, and the file extension must also be an allowed image type. Other files are skipped and reported. See "Error Reports".
  2. File names are normalized. File names can only contain letters in the set: [a-zA-Z0-9._-]. Any letters not in the set are converted to a "", and repeated "" are collapsed.
  3. Existing files are never overwritten. "1", "2", … is added to the base name instead.

If a post is created, the images are attached to it, and the first image is the post's Featured Image.

Error Reports

Errors found while a form is processed are collected, and then sent in one email after the submission is done. They are not saved in the database, not added to the post, and not written to the PHP error log.

The email subject is "Contact 2 Post errors: FormTitle". No email is sent if there were no errors.

  • The site's admin email (Settings > General > Administration Email Address) gets all the errors.
  • The submitter gets a copy at the address in the form's your-email field. They only get the errors about their submission:
    • an uploaded file was not saved (wrong type, copy failed, or not added to the Media Library)
    • an invalid expire-date
  • These site setup errors only go to the admin email:
    • post_template is not set for the form
    • the post_template page was not found
    • ATTR-END was not found in the template
    • the post could not be created (wp_insert_post failed)
  • The submitter does not get a copy if: the form has no your-email field, the value is not a valid email address, it is the same as the admin email, or the submission was marked as spam.

Upload errors are sent even when create_post is not set.

The emails are sent with wp_mail(), so the site must be able to send email. If emails are not received, install an SMTP plugin.
