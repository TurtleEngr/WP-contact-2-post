* Contact 2 Post Development

- First fork the https://turtleengr.github.io/WP-contact-2-post/
  repository.

** Requirements for building

*** Packages
- Install these packages
  + =emacs= (org-mode) - if you want to edit the *.org files
  + =git=
  + =git-flow= - optional
  + =make=
  + =pandoc= - convert org files to markdown format
  + =perl=
  + =php= - for the pod2* programs
  + =pod2markdown= - libpod-markdown-perl pkg
  + =pod2pdf= - optional
  + =sed=
  + =tidy=
  + =zip=

*** Custom Scripts
- The scripts in ./bin and are used in Makefile
  + =bin/org2html.sh= - convert org files to html
  + =bin/rm-trailing-sp= - an convert tabs to spaces
  + =bin/pre-commit= - enforces some basic formatting (see [gitproj "hook"])

- Copy =bin/pre-commit= to =WP-contact-2-post/.git/hooks=

*** git config
+ Append contents of =./bin/gitconfig= to =./.git/config=

#+begin_example
[alias]
    br = branch
    ci = commit
    co = checkout
    df = diff

#+end_example

+ If using git-flow, first time setup, run:
  + =git flow init=

** To Build

*** Modify the Makefile
- Define the location of where the plugin's zip file will be saved.

#+begin_example
mServer = moria.whyayh.com
mPubDev = /rel/development/software/own/$(mProj)
mPubRel = /rel/released/software/own/$(mProj)
#+end_example

*** Build steps

**** =make=
+ This will verify the required packages and files exist.
+ Then it will list the main steps to make and deploy the plugin.

**** =make update=
+ Pull the latest develop branch from github

**** =make build=
+ Create a branch, if there are major changes
+ Build the zip file in the dist/ dir
+ Change files and repeat until it is worth saving

**** =make save=
+ Save a development version for testing.
+ Checkin all changes, push to github
+ Publish to the release server (change mServer to your release server).

**** =make publish=
+ This can only be done on the develop branch (i.e. merged branches)
+ Save a stable (tested) development version
+ Tag the version, push to develop
+ Merge develop to main (which is a stable development version)

**** =make release=
+ if accepted by WordPress.org TBD
+ copy the relevant files to SVN...

*** How it works

+ For details on how this code was generated by Claude, with
  references to the existing plugins it needs, see the files in the
  spec/ directory.

+ The "save image upload" code was referenced from
  https://wordpress.org/plugins/store-file-uploads-for-contact-form-7/
  by Mircea N. (version 1.3.0). That code was then enhanced to
  normalize the image file names and to prevent overwriting existing
  images.

+ The post author is the user with the site's =admin_email=.

+ If publish-date is valid, the date is fixed (=post_date_gmt= is set),
  so publishing keeps it; a future date makes the post "Scheduled".
  If there is no valid publish-date, the post date "floats": it is
  set when the post is published.

+ =cx2p_fOnBeforeCf7SendMail()= is hooked to
  =wpcf7_before_send_mail=. It saves each uploaded image with
  =cx2p_fCreateAttachment()=, and collects the attachment IDs with
  =cx2p_fSaveAttachId()=.

+ Error messages are saved with =cx2p_fErrorLog($pMsg, $pAdminOnly)=.
  Calling =cx2p_fErrorLog()= with no argument returns the list:
  =[[msg, adminOnly], ...]=. The list is a =static= variable, and
  each form submission is one PHP request with its own memory, so an
  email only has the errors from its own submission, even when
  several people submit at the same time. The errors are not saved
  in the database, not added to the post, and not written to the PHP
  error log.
  + Submission errors (uploaded file not saved, invalid expire-date)
    use =$pAdminOnly= false.
  + Site setup errors (=post_template= not set, template page not
    found, ATTR-END not found, =wp_insert_post= failed) use
    =$pAdminOnly= true.

+ =cx2p_fSendErrors()= is hooked to =wpcf7_submit= at priority 20,
  after Flamingo (priority 10, which fires =wpcf7_after_flamingo=), so
  all errors are collected. It runs even when =create_post= is not set
  or Flamingo does not store the message. If there are errors, it
  sends them with =wp_mail()=:
  + to the site's =admin_email=: all errors.
  + to the form's =your-email= field: only the errors that are not
    admin-only. Not sent for spam, if the address is not valid
    (=is_email()=), or if it is the same as the admin email.

+ These filters can change how uploads are saved:
  =cx2p_fCreateAttachment_file_name= (the destination path),
  =cx2p_should_skip_save_attachment_to_media_library= (return true to
  only copy the file), and =cx2p_before_insert_attachment= (the
  attachment array).

+ Flamingo saves the message in =wpcf7_submit=, then fires
  =wpcf7_after_flamingo= with =flamingo_inbound_id=. This plugin hooks
  that action, so no post is made when Flamingo does not store the
  message (=do_not_store: true=), or for spam.

+ The form's "=create_post=" and "=post_template=" Additional Settings
  are read with =WPCF7_ContactForm::is_true()= and =pref()=.

+ The template page is split with =parse_blocks()=. Attribute blocks
  are removed, {field} is replaced only in the block HTML (not in the
  block comment JSON), then =serialize_blocks()=.

*** Test
- test/setup.php and test/submit.php are run with wp-cli on a test
  site with all the plugins active. They are not in the dist zip.

#+BEGIN_SRC bash
wp eval-file test/setup.php
wp eval-file test/submit.php full attach   # post, attachment, expiry
wp eval-file test/submit.php notitle       # title UNDEFINED
wp eval-file test/submit.php nostore       # no post
wp eval-file test/submit.php nocreate      # no post
wp eval-file test/submit.php badslug       # no post, error emailed to admin
wp eval-file test/submit.php full spam     # no post
wp post list --post_type=post --post_status=pending
#+END_SRC
